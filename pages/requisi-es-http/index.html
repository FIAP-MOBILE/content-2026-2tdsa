Mobile App Development

Existem algumas formas de se fazer requisições HTTP no React Native.
Abordaremos aqui duas formas mais comuns: usando o fetch e usando o axios.

O fetch é uma API que já vem nativamente dentro do Javascript. Disponibiliza uma interface onde se faz a requisição (request) e resposta (response).
Para fazer uma requisição, basta chamar o metódo fetch(), sendo obrigatório apenas a url a qual se deseja fazer a requisição.
O retorno de um fetch sempre será um objeto Promise, que é a representação de uma operação assíncrona que tem 3 estados: pendente, concluído e rejeitado.

Então podemos fazer uma requisição fetch de duas formas:

TypeScript
123456789101112131415161718
// Sem uso de async
const fetchData = () => {
  fetch('https://servicodados.ibge.gov.br/api/v2/censos/nomes/joao')
    .then((response) => console.log(response))
    .catch((error) => console.log(error));
};

// Com uso de async
const fetchData = async () => {
  try {
    const response = await fetch(
      'https://servicodados.ibge.gov.br/api/v2/censos/nomes/joao',
    );
    console.log(response);
  } catch (error) {
    console.log(error);
  }
};

Quando fazemos a requisição, podemos ver o contéudo da resposta de duas formas:
response.text() => Traz o conteúdo exatamente como foi retornado pelo servidor
response.json() => Converte o conteúdo retornado do servidor em JSON

Vale ressaltar que ambos os metódos também são objetos do tipo Promise, ou seja, se precisar do retorno deles, deve-se usar a palavra await. Exemplo:

TypeScript
1
const data = await response.json();

O fetch por padrão faz requisições com o metódo GET, mas é possível usar os outros mais
comuns: POST, PUT e DELETE. O segundo argumento da função fetch onde você pode passar um objeto com as opções da sua requisição. As mais comuns são:
method: Define qual metódo deve ser feita a requisição
body: Define qual o conteúdo que vai na sua requisição
headers: Define quais cabeçalhos irão na sua requisição, como tipo de contéudo, autenticação, etc.

O axios por sua vez é uma das bibliotecas mais populares para se fazer requisição.
Tem os mesmos recursos que o fetch e alguns mais que o tornam uma opção mais utilizada pela comunidade. E como é uma biblioteca, para conseguir utilizar no seu projeto, basta rodar o comando:

Terminal
bash
1
npm install axios

Uma vez o axios instalado na sua aplicação, para utiliza-lo basta importa-lo no seu código:

TypeScript
1
import axios from 'axios';

Assim como no fetch, quando fazemos uma requisição usando o axios ele também retorna um objeto Promise. Então para fazer uma requisição, existem duas formas de tratar a resposta:

TypeScript
123456789101112131415161718192021
// Sem uso de async
import axios from 'axios';

const fetchData = () => {
  axios
    .get('https://servicodados.ibge.gov.br/api/v2/censos/nomes/joao')
    .then((response) => console.log(response))
    .catch((error) => console.log(error));
};

// Com uso de async
const fetchData = async () => {
  try {
    const response = await axios.get(
      'https://servicodados.ibge.gov.br/api/v2/censos/nomes/joao',
    );
    console.log(response);
  } catch (error) {
    console.log(error);
  }
};

Para ver o conteúdo da resposta, no axios é bem mais simples. Existe a propriedade data que já faz o tratamento dos dados. Se o conteúdo for um texto, ele não faz nada e retorna o conteúdo normalmente. Caso o conteúdo seja um JSON, ele trata isso e já te retorna no formato JSON.
Exemplo:

TypeScript
1234
const response = await axios.get(
  'https://servicodados.ibge.gov.br/api/v2/censos/nomes/joao',
);
console.log(response.data);

Uma vantagem do axios é ser possível criar uma nova instância e deixar algumas configurações pré-definidas. Por exemplo, qual o servidor que você vai fazer a requisição e qual o caminho base. Veja o código a seguir:

TypeScript
12345
const client = axios.create({
  baseURL: 'https://servicodados.ibge.gov.br/api/v2',
});
const response = await client.get('/censos/nome/joao');
console.log(response.data);

É criado um cliente para fazer as requisições e todas as requisições serão feitas no servidor definido no parâmetro baseURL. O parâmetro baseURL vai ser concatenado com o argumento que será informado no momento que uma requisição for realizada.

Para fazer os diferentes tipos de requisição, no axios existe um metódo para cada um deles.
axios.get => Requisição GET
axios.post => Requisição POST
axios.put => Requisição PUT
axios.delete => Requisição DELETE

Caso o código seja feito utilizando TypeScript, um recurso interessante do axios é que ele permite definir a estrutura dos dados que serão retornados utilizando um type. Exemplo:

TypeScript
1234567891011
import axios from 'axios';

type User = {
  firstName: string;
  lastName: string;
};

const getData = async () => {
  const { data } = await axios.get<User>('https://dummyjson.com/users/1');
  console.log(data.firstName);
};

Outro recurso muito interessante do axios são os interceptors. Como o nome sugere, é possível interceptar uma requisição ou uma resposta.

TypeScript
123456789101112131415161718192021222324
// Antes do request
axios.interceptors.request.use(
  (config) => {
    // Coloque qualquer código aqui para executar antes da requisição ser feita
    return config;
  },
  (error) => {
    // Faça o tratamento de erro caso a requisição tenha dado errado
    return Promise.reject(error);
  },
);

// Quando se recebe a resposta
axios.interceptors.response.use(
  (response) => {
    // Esse código só é executado quando o status é 2xx
    // Trate a resposta como achar conveniente
    return response;
  },
  (error) => {
    // Faça o tratamento de erro caso o status da resposta seja diferente de 2xx
    return Promise.reject(error);
  },
);

Vale ressaltar dois pontos sobre interceptors

  • Quando se configura um interceptor para request, deve obrigatoriamente retornar o config que é passado como paramêtro.
  • Não tem limitação de quantos interceptors podem ser executados. A ordem de execução dos interceptors vai depender da ordem em que eles foram adicionados.
TypeScript
12345678910111213141516171819
axios.interceptors.request.use((config) => {
  console.log('Segundo interceptor');
  return config;
});

axios.interceptors.request.use((config) => {
  console.log('Primeiro interceptor');
  return config;
});

axios.interceptors.response.use((config) => {
  console.log('Primeiro interceptor');
  return config;
});

axios.interceptors.response.use((config) => {
  console.log('Segundo interceptor');
  return config;
});

Seguindo a premissa de que se lê o código de cima pra baixo:

  • No caso de um interceptor de request, o primeiro a ser executado é último a ser declarado, ou seja, na ordem de baixo pra cima
  • No caso de um interceptor de response, o primeiro a ser executado é o primeiro a ser declarado, ou seja, na ordem de cima pra baixo
